## 1. Overview
A **Windows-native** (.NET 8, C#) NVIDIA GPU monitor that talks **directly** to the
NVIDIA Management Library (`nvml.dll`) via P/Invoke — it never shells out to
`nvidia-smi`. Two front-ends share one NVML engine:
- **`NvidiaMonitor`** — a WPF live dashboard (overview grid, synchronized line
  charts), polling ~1 Hz. It opens on the **Charts** tab at a **calculated
  fit-to-content window size** (never maximized; sized so no scrollbar is needed at
  first launch — and every scrollbar's 13 px is reserved from the first layout, so the
  window never grows when data arrives); a **per-device list** (CUDA ordinal + card name
  **plus that card's own max memory in MiB**, with a colour swatch matching each GPU's
  chart series) sits at the **top-right of the header
  row**; the **Processes** and
  **Log** tabs have been removed (the engine's `AppLog` activity logging remains,
  but is no longer surfaced as a tab). Every chart card also carries a **chevron
  "dropbox" at its top-left** that collapses the card down to just its header row, and
  **only Memory Utilization and Memory Used open expanded — the other seven cards start
  collapsed** (T20 + T21, refined by T22), which is what keeps the calculated fit-to-content window short.
- **`NvmlTest`** — a headless console CLI that prints a one-shot `nvidia-smi`-style
  table, a live `--watch` feed (the interval defaults to 1 s when omitted), or a
  one-shot `--probe` diagnostic (NVML version, both SM-utilization NVML APIs, and the
  batch API's version-constant sweep).

Reads per-GPU telemetry: GPU/memory utilization, **SM utilization** (per-process sum, clamped at 100), temperature, power (+limits), memory
used/total/free, clocks, fan, P-state, **PCIe link (gen × width)** and derived
theoretical **PCIe bandwidth (GB/s)**, ECC, NVLink count, throttle reasons, and a
per-GPU process list (compute + graphics) with PID, kind and memory. When NVML/GPU is
unavailable it degrades to a friendly message (UI) or a non-zero exit code (CLI).

## 2. Tech Stack
- **Language / runtime:** C# / .NET 8. `net8.0` for the two libraries + CLI;
  `net8.0-windows` with `UseWPF` for the dashboard.
- **UI:** WPF built **entirely in C# code** — no XAML files. Charts are native
  `System.Windows.Shapes` (Canvas/Polyline/Line) + `System.Windows.Controls`; **no
  third-party charting or NuGet packages at all**.
- **GPU access:** P/Invoke to the OS `nvml.dll` (loaded at runtime).
- **Nullable:** enabled. **ImplicitUsings:** enabled (a per-project `GlobalUsings.cs`
  adds the WPF namespaces for the dashboard).
- **Strictness:** `TreatWarningsAsErrors=true` in `Contracts` and `NvmlCore`
  (their builds must be warning-free).

## 4. Entry Points
- **WPF dashboard:** `NvidiaMonitor` → `App.Main` (`[STAThread]`). No args = launches
  `MainWindow` at a **calculated fit-to-content size** (never maximized; the no-NVML
  fallback screen keeps the 1040×640 default) with the green "slide" scrollbars
  (**always visible** — T14 reserved each bar's 13 px from the first layout, so the
  window never grows when the chart timelines outgrow the view);
  `--print` = headless single refresh printing a one-line summary per
  GPU (includes `sm=` — SM utilization; never opens a window), exit 0 on success / 1 when NVML unavailable.
- **CLI:** `NvmlTest` → `Program.Main`. `--print` = one-shot nvidia-smi-style table;
  `--print --watch [<seconds>]` = live feed that re-prints the table every N seconds
  until Ctrl-C (**N defaults to 1** when the value is omitted; an explicit
  non-numeric value exits 2). Exits 0 on success, 1 when NVML/GPU unavailable
  (reason on stdout). `--probe` = one-shot NVML diagnostic (versions + both SM-utilization APIs).

*is* the manual integration check — it verifies NVML end-to-end without a window
(driver / CUDA / NVML versions + per-GPU metrics).

## 6. Architecture & Data Flow
```
nvml.dll (OS, P/Invoke — from %CommonProgramFiles(x86)%\NVIDIA Corporation\NVSMI or System32)
  └─ NvmlCore: NvmlLoader → NvmlDelegates/Types/Error → NvmlCoreService : IGpuMonitorService
       │   RefreshAsync() → GpuSnapshot ; status-change events ; AppLog activity
       ├─ NvmlTest (CLI):  Program → SmiFormatter → stdout table
       └─ NvidiaMonitor (WPF): GpuServiceFactory → NvmlCoreService
            └─ GpuPollingService (~1 Hz background) → GpuHistory (per-GPU ring buffer, cap 720)
                 └─ MainWindow (Dispatcher-marshalled)
                      ├─ Overview: all-GPU grid (GpuRow view-models; N/A-aware)
                      └─ Charts:   ChartController (shared timeline/zoom/crosshair/scroll)
                                   driving 9 MetricChart cards (mem-used [% of that card's own memory → FIRST], GPU-util,
                                   mem-util, temp, SM-util, power, PCIe-bandwidth [log Y], GPU-clock, mem-clock — all but mem-used and mem-util start collapsed, see T20/T21/T22) — native WPF shapes
```
Key boundary: **`Contracts` is the only surface both front-ends depend on**
(`IGpuMonitorService` + the snapshot/sample/history types). `NvmlCore` is the only
implementation of that contract. `NvidiaMonitor` and `NvmlTest` never touch
`nvml.dll` directly — they consume the contract.

## 7. Key Contracts & Types
- `IGpuMonitorService` — the service surface: `InitializeAsync()`, `RefreshAsync() →
  GpuSnapshot`, `ShutdownAsync()`, `IsAvailable`, `StatusMessage`, plus a
  status-change event and an `AppLog` hook.
- `GpuSnapshot` — driver/CUDA/NVML versions + `GpuCount` + `Gpus[]` (per-GPU metrics, incl. `SmUtilizationPct`).
- `GpuMetricSample` — one timestamped sample of every metric (feeds history); it also
  carries the per-GPU `MemoryTotalBytes` and `PowerCapWatts` (the denominators behind
  the charts' percentage readouts) — plus `SmUtilizationPct` and `MemoryClockMhz`
  (the SM and memory-clock charts). Since T20 the **Memory Used** chart plots
  `MemoryUsedBytes / MemoryTotalBytes × 100` itself, so that card's own total is also
  the fixed 0-100 % axis behind it.
- `GpuHistory` — per-GPU **ring buffer** (`new GpuHistory(capacity)`; the dashboard
  uses 720 ≈ 12 min @ 1 Hz). `GetSeries(gpu) → IReadOnlyList<GpuMetricSample>`
  (oldest→newest), `GetSampleTimestamps(gpu)`, `GpuIndices`. The charts plot over the
  real "seconds since start" timeline derived from these.
- `GpuProcessInfo` — one process on a GPU (pid, kind, memory).
- `DisplayValue` — N/A-aware value rendering; `Exporter` — CSV/XML serialization.

## 8. Configuration
No config files / no `appsettings`. Runtime behavior is driven by:
- **NVML library location** — auto-discovered by `NvmlLoader`
  (`%CommonProgramFiles(x86)%\NVIDIA Corporation\NVSMI`, fallback `System32`).
- **Polling rate** — `GpuPollingService` (~1 Hz, constant).
- **Chart window** — `ChartController.WindowMinutes` (2–60, default 10); `Ctrl+wheel`
  rescales it; history ring-buffer capacity 720.
- **Repo asset storage (VCS, not runtime)** — `.gitattributes` routes `*.png` through **Git LFS**

  other binary type yet.

## 10. Conventions & Gotchas
- **Single-instance GUI guard (T25):** `App.cs` keeps at most one `NvidiaMonitor` window
  alive at a time via a lockfile heartbeat — `%TEMP%\NvidiaMonitor.lock` is created on
  launch and refreshed every ~1 Hz poll tick (`MainWindow.OnLoaded`/`ApplySnapshot` →
  `App.RefreshInstanceLock()`); its mtime is the liveness stamp. A new GUI launch reads
  the stamp (`AnotherInstanceRunning()`) and prints a refusal message + exits (code 0) if
  it was written <6 s ago. Headless `--print` never touches the lock. **Gotcha:** static
  field init order matters — `TEMP` must be declared *before* `LockPath` (and falls back
  to `C:\Windows\Temp` when `%TEMP%` is absent, e.g. PowerShell-launched children).
- **No XAML** — all WPF UI is built in C# (the entry point is `App.cs`, a code-only
  `partial class App : Application` with an explicit `[STAThread] Main`; there is no
  `App.xaml`).
- **Never shell out to `nvidia-smi`** — all reads go through the P/Invoke engine.
- `ref/nvml.h` is the **authoritative** NVML reference; don't hand-edit P/Invoke
  signatures to diverge from it.
- **NVML version constants:** *Info*-struct version fields encode
  `struct-size | (1 << 24)` — the 24-byte v1
  `nvmlDeviceProcessUtilizationInfo_t` is `24 | (1 << 24)` (= 16777240; the old
  16777264 was 48-based and wrong). The batched
  `nvmlDeviceGetProcessesUtilizationInfo` rejects any other encoding with
  `NVML_ERROR_ARGUMENT_VERSION_MISMATCH` (rc 25). The engine therefore reads SM
  utilization through the **legacy two-phase** `nvmlDeviceGetProcessUtilization`
  (NULL-probe → filled read; the loop must count the samples the driver *wrote*,
  which can be fewer than requested), with the batched API as fallback.
- **`TreatWarningsAsErrors`** is on for `Contracts` and `NvmlCore` — their builds must
  stay warning-free (the dashboard/CLI projects are not).
- **Threading:** `NvmlCoreService` is polled off the UI thread by `GpuPollingService`;
  results are **marshalled to the UI thread** (Dispatcher) in `MainWindow`. The
  `--print` paths never construct a WPF window.
- **N/A, not exceptions:** metrics NVML can't report render as `N/A`
  (`DisplayValue`); a single missing value never aborts the whole read.
- **Charts** (`ChartController.cs`): `ChartController` owns *shared* state (one
  timeline, one visible window, one pixels-per-second scale, synchronized scroll, one
  red crosshair); each `MetricChart` (a `Border` subclass) draws one metric with one
  polyline per GPU. `SetSeries` only stores data; the controller's `OnDataTick()`
  resizes then redraws all charts. Drag-and-drop reorder is handled per chart panel.
  Layout: a **fixed right-hand Y-axis** column (a non-scrolling `Canvas` beside the
  plot) shows value labels + tick marks in **white** (`Theme.White`) — the scale spans
  the **full plot height** (max value at `y = 0`, zero at `y = PlotH = 128`; the topmost
  tick label is clamped to `y ≥ 1` so it is never clipped): linear charts = evenly
  spaced 0…max; the log-scale PCIe chart = powers of two (1G, 2G, 4G, 8G, 16G,
  32G …). The **t = 0** marker is a normal `MinuteBlue`
  (1 px) vertical line with a `MinuteLabel` "0m" — the same styling as the other
  per-minute gridlines (light blue). The PCIe chart carries **per-sample link
  gen/width** (`GpuMetricSample.PcieLinkGen/Width`) so the **legend and hover readout
  show the link config** (e.g. `4.0 x16`) for current and historical points, formatted
  by `GpuSnapshot.PcieLinkLabel(gen,width)` and appended after **one** space
  (`4.0GB/s [1.0 x16]`). The **follow-right** pin keeps the view
  on the newest data until the user scrolls into history: programmatic pin targets
  are remembered per chart (`_progOffset`) and `OnPlotScroll` treats a
  `ScrollChanged` as programmatic only when it lands within 8 px of the queued target
  **and** travelled ≤ 30 px (WPF applies the scroll in a later layout pass, after
  `_syncing` is cleared, so without this the pin re-application was misread as a
  user gesture and permanently killed following); `OnDataTick()` forces
  `UpdateLayout()` before re-pinning (so `ScrollableWidth` is current) and re-pins
  when the content range grows while following (fixes the "left-aligned at 10 min"
  scroll race). The **legend and hover readout** show the per-GPU value (the
  **Memory Used** and **Power** charts additionally show **`(NN %)`** of the
  per-GPU total memory / enforced power cap, omitted when the denominator is N/A);
  the **legend text is pure white** (`Theme.White`) and the **"max N" readout** at the
  legend's right is **bright yellow** (`Theme.Yellow`, `#ffe14d`) at the same 12 px
  legend size; the **temperature Y-axis is capped at 100 °C** (auto-expanding only if a
  card runs hotter). The per-GPU
  identity (`[index: name]`) that T11 appended to every legend/readout was
  **removed again in T13** — device identity now lives in the **top-right device
  list** (see the T13 change-log entry below). The **window opens at a calculated
  fit-to-content size** (T12 superseded "opens maximized"; T13 fixed the height so
  no scrollbar appears at first launch; T14 reserved every scrollbar's 13 px from the
  first layout — `Visible`, not `Auto` — so the window never grows when data arrives).
  **Collapsible cards (T20)**: each `MetricChart` owns a chevron button (`_toggle`, a
  16 px `Border` over a `Canvas` holding two `Line`s that share a pivot) added as the
  **first `Dock.Left` child of its header row**, so it sits at the card's top-left;
  `SetCollapsed(true)` pins `_inner` row 1 to `GridLength(0)` **and** hides `_body`
  (hiding alone still participates in layout, and `Grid` never clips cell content),
  tightens the card's bottom margin, flips the chevron down→right, and takes the cheap
  `Redraw()` path that refreshes only the legend + "max" and clears the red crosshair
  readout (the line itself lives in the hidden plot). `MainWindow` opens Temperature,
  SM Utilization, GPU Clock and Memory Clock collapsed; the card's drag handler
  ignores presses inside the chevron box, so toggling never starts a reorder drag.
  **Memory Used is a percentage chart (T20)**: it plots `used / total × 100` with that
  card's **own** `MemoryTotalBytes` (from `nvmlDeviceGetMemoryInfo`) using a **double**
  division — `long/long` would truncate to 0/1 — on the fixed 0-100 axis, and
  `MetricChart._pctValue` (set through `ChartSpec.PctValue`) makes its legend/hover
  readout **`NN% (MMMM MiB)`** — percent first (no space before `%`, T21), the absolute
  amount in parentheses; the Power chart keeps the old `NN.N W (NN %)` shape.
  **T21 chart tweaks (all in `MainWindow.cs`)**: the Memory-Used spec's `Unit` is `"%"`
  (not `" %"`) so legend/hover read `80% (19739 MiB)`; **Memory Used is spec index 0**
  (heads the stack) and `_runningMax`'s order comment was rewritten to match — memUsed,
  util, memUtil, temp, smUtil, power, pcieBw, clock, memClock (the literal itself stayed
  `{100,100,100,100,100,400,32,2100,1600}`); Memory Utilization, PCIe Bandwidth and
  Power also start `Collapsed: true`, so **7 of 9 cards open collapsed** (only GPU
  Utilization + Memory Used expanded ≈ 672 px of chart stack); and the top-right
  **device list now prints each card's own max memory** after its name —
  `cuda:0  NVIDIA GeForce RTX 3090 (24576 MiB)` (muted `Run`, `Theme.Mb(g.MemoryTotalBytes)`,
  `" (N/A)"` when unknown) — i.e. exactly the denominator that card's percent series divides by.
  **T22 corrected which card is collapsed**: the `Collapsed: true` flag moved **off**
  Memory Utilization and **onto** GPU Utilization, so the Charts tab opens with **Memory Used
  + Memory Utilization** expanded and every other card (GPU Utilization included) at its
  header row — still 7 of 9 collapsed, so the ≈ 672 px stack and the fit-to-content window
  are unchanged, and spec order / `_runningMax` were not touched.
- `bin/` is **git-ignored** and produced by `dotnet publish`, not by `dotnet build`.

  under "Planned (next iteration)", but they are now implemented in `NvidiaMonitor`
